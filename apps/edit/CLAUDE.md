# prodrive-edit — AI Race Editing Pipeline

CLI tool that takes raw recordings from the RacingDesk overlay (cockpit video + TV-view video + telemetry JSONL sidecar) and produces broadcast-quality race edits, condensed highlights, and social media clips.

This tool previously lived inside [`prodrive-plugin`](https://github.com/DOOOOM/prodrive-plugin) at `racing-desk-edit/`. It was extracted into its own repo so the editing pipeline can iterate independently from the SimHub plugin and overlay.

## Tech Stack

- **Node.js ESM** — `"type": "module"`, requires Node ≥ 20
- **FFmpeg** — all video operations (segment extraction, concat, encode, silence detection)
- **Claude** (optional) — editorial refinement via `claude` CLI or `@anthropic-ai/sdk`
- **No build step** — run directly with `node bin/racing-desk-edit.js`

## Pipeline Architecture

```
ingest → analyze → render
          ├── scoring-engine (TV Score + Interest Score per second)
          ├── camera hysteresis (mechanical segments)
          ├── silence detection (boring signal)
          ├── claude-director (optional AI refinement)
          └── edl-generator → edit-decisions.json

condense = ingest + interest scoring + threshold adjustment + Claude + render
```

## Claude Integration (Dual-Mode)

The tool supports two Claude integration modes — users choose at runtime:

1. **CLI mode** (default) — pipes prompts to the `claude` CLI tool via stdin. Uses the user's Claude subscription. No API key needed.
2. **SDK mode** — uses `@anthropic-ai/sdk` with `ANTHROPIC_API_KEY`. Better for automation / CI.

Detection order:
- `RACECOR_CLAUDE_MODE=cli|sdk` → explicit override; `none` (what `--no-claude` sets) → mechanical only
- `ANTHROPIC_API_KEY` set → SDK mode
- `claude` on PATH → CLI mode
- Neither → mechanical-only (no AI refinement, still works)

The SDK (`@anthropic-ai/sdk`) is in `optionalDependencies` — if it's not installed, CLI mode still works. Both modes fall back gracefully to mechanical scoring if Claude is unavailable.

## Scoring System

Two parallel scoring engines run per-second over telemetry frames:

- **TV Score (0–100)**: Camera switching preference. High = show TV view (battles, overtakes). Low = stay on cockpit.
- **Interest Score (0–100)**: Viewer engagement. High = keep in condensed edit. Low = cut.

Both use weighted signal detection (gap proximity, position changes, incidents, flags, speed drops, clean air, etc.) with configurable thresholds and hysteresis to prevent rapid switching.

## Input Format

Expects a session directory — since 2026-10-01 the folder Racing Desk files each OBS recording in
(`D:\Racing Desk\Recordings\<date track car>\`, see `docs/recording.md`) — containing:
- `.telemetry.jsonl` — the sidecar Racing Desk writes beside the file OBS records (a header line, one JSON object per
  frame, a summary line last; the header and a `resumed` line are not frames). The recording's own sidecar is read; a
  replay clip's (`Replay …`) or the TV take's (`… tv`) only when there is no other.
- `.mp4` / `.webm` — the cockpit recording, the TV take (`… tv.mp4`), and the replay clips (`Replay …`, listed as
  `sources.clips`, never taken for the TV view)
- `session.json` — generated by `ingest` command

## What a frame's values mean

The sidecar writes 0 for a number the payload did not have and `none` for a flag word it did not have
(`telemetry-sidecar.js`), and the file goes on after the race: the cool-down lap, the pits, the menus, with the lap
counter on to the next and then 1, and a position of -1 once he is out of the session. Read as they stand, his
2026-10-27 Zandvoort race came out "P8 → P-1", with 40 flag changes, two battles in the cool-down and the TV view for
98.6 % of it (the gap behind was 0 in every frame, read as a car on his tail, and `none` was read as a flag out). So
`src/ingest/frame-values.js` says what they mean, and the detector, the scorer and the session's numbers read them there:
- **A gap of 0 is no gap known** (`knownGap`): no car there, or no source. Never a battle or a car alongside; with
  none known either side it is clean air. A real gap of 0.002 s is a gap.
- **A position of 0 or -1 is none** (`knownPosition`): the session's start and end positions are the first and last
  known in the race.
- **`none` is no flag, as green is** (`isNoFlag`). Only a caution (yellow, red: `isCaution`) scores as a flag, and only a
  flag that changes his race is a flag-change event (`RACE_FLAGS`: yellow, red, white, chequered, black, meatball — not
  debris, out at a sector every lap, nor blue, nor the host's orange), not again within 30 s of last showing (iRacing
  gives one word at a time, and white and blue take turns on the last lap while he is lapped).
- **The race ends at his chequered flag** (`finishTime`, the first frame with `endOfRace`): the race-end event is that
  frame, with his position and lap there; after it no battle, pass, pit stop, lap or off is found; ten seconds after it
  (`FINISH_HOLD_SEC`) every second scores 0. The session's laps are the lap he took the flag on (the counter moves on
  a few seconds later); its incidents and cars are the most the race saw.
- **The start is lap 1 from the grid** (`raceStartTime`: lap 0 → 1, or a recording begun on lap 1; none for one begun
  later), and the start's TV and interest weight is its first minute (`START_HOLD_SEC`), not the whole of lap 1.
- **Highlights**: a battle's is 20 s around its closest moment (`closestAt`), not all of a battle that ran for minutes,
  and highlights that overlap are one, their labels joined. The reel is still the first five moments, in order.

Tests: `tests/sidecar-values.test.js`, frames shaped on his Zandvoort and Road Atlanta races. Through the editor, his
three newest kinds of session (read from copies, 2026-10-28): Zandvoort P8 → P8, 14 laps, 2 flag changes, the one battle
on the last lap, TV 0.3 %; Road Atlanta P10 → P9, the opening pack's battle as 24 s at the start, TV 18.4 %; a solo
Nordschleife session TV 2.7 % (was 27 %, all of an eight-minute lap 1).

## Telemetry time and video time

Everything the pipeline decides (events, scores, segments, the cuts in `edit-decisions.json`) is in the sidecar's
time: a frame's `t`, seconds from the moment OBS said the recording had started. The file need not begin then (an
output joining a running encoder waits for the next keyframe; his eight recordings to 2026-10-27 measured −8 to +19 ms),
and a paused recording's file stood still while the sidecar went on (the TV takes' are paused between moments). So **one module turns the one into the other**, `src/utils/video-time.js`
(`videoClock` from the last summary, `toVideoTime`, `toSidecarTime`, `videoRange`): video time is `t` plus the
summary's `videoOffsetMs`, less the lengths of the `pauses` before it, and a moment inside a pause is where the video
stopped (docs/telemetry-sidecar-schema.md). It is used in two places and no others:
- **The render** (`planSegments` in `src/render/ffmpeg-assembly.js`): each cut becomes the stretch of the video that
  shows it, held to the file (from 0, to its probed duration); a cut over a pause is one piece, shorter by it; one
  before the file began, past its end or wholly inside a pause is skipped and said.
- **The condenser's silences**, which ffmpeg finds in the video's time, turned back to `t` before they lower a score.

A sidecar with no summary, or one lined up by nothing (`alignment.method: "none"`), is read with `t` as video time,
as everything was before, and `ingest` says which it is ("Video is telemetry time −3500 ms (lined up by chapters).").
**The TV view is cut by this clock only where it was recorded beside the cockpit** (a recording from before OBS, with
no offset): a TV take is the replay's moments one after another on a clock of its own, and any other second file of
an OBS recording (a split) is not the cockpit's, so a `tv` cut is taken from the cockpit and the render says so.
Cutting from a TV take by its own sidecar (`sn`, `st`, its `pauses`) is not built. The EDL's times are still whole
seconds (`formatDuration`); the clock adds the offset to them to the millisecond.

## Commands

```bash
node bin/racing-desk-edit.js <command> <dir>     # or: npm start -w racing-desk-edit -- <command> <dir>
racing-desk-edit ingest <dir>                    # Parse telemetry, detect events → session.json
racing-desk-edit analyze <dir>                   # Score + Claude → edit-decisions.json (ingests first if needed)
racing-desk-edit preview <dir>                   # 480p draft, each cut with its telemetry and video timecodes
racing-desk-edit render <dir>                    # Full-res final edit (--resolution, --quality, --output)
racing-desk-edit condense <dir> --target 5:00    # Smart-cut to target duration and render it
racing-desk-edit clips <dir> --social            # Each highlight as clip-01.mp4…, with 9:16 copies
racing-desk-edit render <dir> --dry-run          # List the cuts in the video's time; render nothing
racing-desk-edit analyze <dir> --no-claude       # The mechanical edit only
```

`bin/` is tracked through `apps/edit/.gitignore` (`!bin/`): the root ignores `bin/` for .NET build output, which kept
the entry point out of git from the start. Exit codes: 0 done, 1 the command failed (said on stderr), 2 a usage error.
Tests: `tests/video-time.test.js` (the conversion), `tests/render-plan.test.js` (cuts to segments),
`tests/cli.test.js` (the commands over a made-up folder, `--no-claude`), `tests/render-timing.test.js` (a real cut
through ffmpeg from a video made in the test, whose brightness is its time; skipped without ffmpeg on PATH; libx264).
